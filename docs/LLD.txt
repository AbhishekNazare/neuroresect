# NeuroResect

## Low-Level Design — Patient-Specific Virtual Resection & Brain-Network Analysis Platform

**Document Type:** Low-Level Design
**Parent Document:** NeuroResect HLD
**Primary Stack:** Next.js + React + TypeScript + React Three Fiber + FastAPI + Python + PostgreSQL + Redis + Celery + MinIO
**Primary Scientific Stack:** NumPy, Pandas, NiBabel, Nilearn, NetworkX/igraph, scikit-learn, XGBoost, SHAP, MLflow
**Initial Dataset Scope:** De-identified epilepsy structural-connectome/resection datasets
**Initial Modality:** DWI-derived structural connectivity
**Future Modalities:** MEG, fMRI, HGM, EEG, clinical features

---

# 1. LLD Objectives

This document defines how the NeuroResect HLD is implemented at the level of:

* backend modules;
* classes and interfaces;
* API contracts;
* database tables;
* object-storage layouts;
* asynchronous jobs;
* scientific algorithms;
* ML workflows;
* experiment provenance;
* frontend modules;
* 3D rendering components;
* client-side state;
* event flows;
* caching;
* errors;
* security;
* tests;
* observability;
* deployment.

The architecture should satisfy three principles:

### Principle 1 — Science must remain independent from the UI

The virtual-resection engine should work from the command line even if the React application does not exist.

### Principle 2 — Every result must be reproducible

Any prediction or metric shown in the frontend must trace back to:

```text
dataset
+
patient
+
atlas
+
resection
+
feature pipeline
+
model
+
code/version
+
configuration
```

### Principle 3 — Clinical-looking UI must never imply clinical validation

Every prediction is presented as:

```text
Research output
```

not:

```text
Clinical recommendation
```

# 16. Binary Resection Algorithm

For each region:

```text
fraction_removed > threshold
    remove node
```

Pseudo-code:

```python
for region in resection.regions:
    if region.fraction_removed >= binary_threshold:
        G.remove_node(region.region_id)
```

Default threshold:

```text
0.5
```

but configurable.

---

# 17. Weighted Resection Algorithm

For region `r`:

```text
f = fraction removed
```

Every incident edge:

```text
new_weight = old_weight × (1 - f)
```

If both endpoint regions are partially resected:

```text
new_weight =
old_weight
× (1 - f_source)
× (1 - f_target)
```

Example:

```text
A removed 40%
B removed 20%

remaining edge =
W × .60 × .80

= W × .48
```

This provides smooth degradation instead of binary deletion.

---

# 18. Edge-Informed Resection

Future implementation receives tract-level involvement.

```python
new_weight = old_weight * (1 - tract_damage_fraction)
```

Requires fiber/tract intersection information.

This stays behind the same `ResectionStrategy` interface.

# 21. Delta Feature Calculator

```python
class DeltaFeatureCalculator:

    def calculate(
        self,
        baseline: GraphMetrics,
        post: GraphMetrics
    ) -> dict[str, float]:
        ...
```

Generic rule:

```text
delta_x = post_x - baseline_x
```

Relative:

```text
relative_delta_x =
(post_x - baseline_x) / baseline_x
```

Protect against division by zero.

Both raw and relative deltas should be stored.


# 41. Counterfactual Objective

Example:

```text
score =
w1 × target_coverage
+
w2 × predicted_outcome
-
w3 × connectivity_loss
-
w4 × hub_damage
```

Constraints:

```text
target coverage >= minimum

number of modified regions <= N

protected regions cannot exceed max removal
```

Again, this is research exploration, not surgical optimization.

---

# 42. Search Algorithm V1

Use beam search.

```text
Initial resection
      ↓
Generate neighboring candidates
      ↓
Evaluate candidates
      ↓
Keep best K
      ↓
Repeat depth D
```

Config:

```text
beam_width = 20

max_depth = 5

max_candidates = 500
```

This is understandable and debuggable.

```sql
    resection_id UUID NOT NULL REFERENCES resections(id),
    region_id INTEGER NOT NULL,
    fraction_removed FLOAT NOT NULL,

    PRIMARY KEY(resection_id, region_id),

    CHECK (
        fraction_removed >= 0
        AND
        fraction_removed <= 1
    )
);
```

# 139. Final Implementation Philosophy

NeuroResect should behave like two products sharing the same core:

### Research Engine

```text
deterministic
testable
reproducible
versioned
scriptable
```

### Interactive Research Workstation

```text
visual
3D
responsive
explorable
intuitive
```

The 3D workstation should never contain scientific logic that cannot also run through the Python research engine.

Likewise, the research engine should never require the UI to produce a valid result.

This separation is what allows NeuroResect to evolve from:

```text
portfolio project
```

into:

```text
research software
```

and potentially eventually into:

```text
a real lab tool.
```
