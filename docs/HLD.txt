# NeuroResect

## Patient-Specific Virtual Resection & Brain Network Analysis Platform for Epilepsy Surgery

**Document Type:** High-Level Design
**System Type:** Research Software / Clinical Decision-Support Research Prototype
**Primary Domain:** Epilepsy surgery, structural connectomics, neuroimaging, machine learning
**Primary Objective:** Simulate patient-specific brain resections, quantify resulting network disruption, compare counterfactual surgical scenarios, and investigate whether network-level changes improve postoperative outcome prediction.

---

# 1. Vision

NeuroResect is an interactive research platform that models a patient's brain as a structural network derived from neuroimaging data.

Researchers can:

* load an epilepsy patient's brain connectome;
* inspect the brain in an interactive 3D environment;
* visualize brain regions and structural connections;
* overlay the patient's actual surgical resection;
* manually design hypothetical resections;
* simulate how those resections alter the structural brain network;
* calculate network disruption;
* predict postoperative outcomes;
* compare multiple surgical scenarios;
* quantify uncertainty;
* examine which brain regions contributed most strongly to predictions;
* run reproducible research experiments across cohorts.

The long-term architecture supports:

* DWI;
* structural MRI;
* MEG;
* fMRI;
* HGM / intracranial electrophysiology;
* clinical variables.

The initial implementation should focus on:

**DWI-derived structural connectomes + actual resection information + patient outcomes.**

---

# 2. Core Research Question

The primary scientific question should be:

> Does patient-specific network disruption caused by surgical resection provide additional predictive information about postoperative epilepsy outcomes beyond standard patient and resection characteristics?

The core experimental comparison:

### Model A — Clinical Baseline

Input:

* age;
* sex;
* epilepsy duration;
* seizure characteristics;
* resection volume;
* affected anatomical regions.

### Model B — Baseline Connectome

Input:

* Model A features;
* preoperative structural connectivity;
* graph topology features.

### Model C — Virtual Resection Model

Input:

* Model A;
* Model B;
* network characteristics after simulated resection;
* delta network characteristics;
* hub-disruption metrics;
* connectivity-loss features.

If Model C consistently outperforms A and B under proper patient-level validation, that becomes an actual research result.

# 3. Seven Core Capabilities

The entire architecture should revolve around the seven major differentiators.

## 3.1 Reproducible Experiments

Every experiment must be reproducible from:

* dataset version;
* patient cohort;
* atlas;
* preprocessing version;
* model;
* hyperparameters;
* random seed;
* feature configuration;
* resection algorithm.

Example:

```text
Experiment: EXP-2026-042

Dataset:
IDEAS-II v1.0

Atlas:
Schaefer-100

Resection:
Weighted

Features:
Clinical
Preoperative Graph
Postoperative Graph
Delta Graph

Model:
XGBoost

Validation:
5-Fold Grouped CV

Seed:
42
```

Every execution produces:

```text
experiment/
├── config.yaml
├── metrics.json
├── predictions.csv
├── feature_importance.csv
├── model.pkl
├── logs/
├── figures/
└── provenance.json
```

This means no result exists without provenance.

# 4. Prevent Patient-Level Data Leakage

Biomedical ML is particularly vulnerable to leakage.

The architecture must enforce:

```text
Patient 1001

Training OR Validation OR Test

Never more than one.
```

If multiple scans, atlases, visits, or derived files exist for the same patient:

```text
patient_id → group_id
```

All samples sharing that group must stay within the same split.

The experiment service should reject configurations that attempt unsafe splitting.

Example:

```text
Requested Split:
RandomSplit ❌

Detected:
Repeated Patient IDs

Recommended:
GroupKFold ✅
```

The UI should visually display:

```text
Data Integrity

✓ Patient-separated folds
✓ No duplicated patient IDs
✓ No post-outcome features in training
✓ No leakage detected
```

This becomes an important part of the project's credibility.

---

# 5. Model Uncertainty

NeuroResect must never display predictions as absolute truths.

Bad:

```text
Surgery successful: YES
```

Better:

```text
Predicted probability of favorable seizure outcome

72%

95% Bootstrap Interval
64% – 79%

Model confidence
Moderate
```

Potential uncertainty mechanisms:

* bootstrap confidence intervals;
* ensemble variance;
* probability calibration;
* conformal prediction;
* Monte Carlo perturbation;
* atlas sensitivity;
* resection-boundary sensitivity.

The platform should distinguish:

```text
Prediction
Confidence
Stability
```

These are different concepts.

Example:

```text
Prediction:
78% favorable

Confidence:
High

Resection Sensitivity:
Low

Atlas Sensitivity:
Moderate
```

# 6. Resection Sensitivity Analysis

Instead of analyzing one exact surgical mask, NeuroResect generates perturbations.

For example:

```text
Original Resection

R0
```

Generate:

```text
R-5mm
R-3mm
R0
R+3mm
R+5mm
```

or anatomical variations:

```text
R0 without hippocampus

R0 + adjacent temporal region

R0 preserving high-centrality hub
```

Each scenario is independently simulated.

Output:

| Scenario | Connectivity Loss | Global Efficiency Δ | Hub Damage | Predicted Favorable Outcome |
| -------- | ----------------: | ------------------: | ---------: | --------------------------: |
| R0       |               21% |                -13% |       0.31 |                         72% |
| R-3mm    |               17% |                 -9% |       0.21 |                         76% |
| R+3mm    |               29% |                -19% |       0.43 |                         61% |

The UI should animate transitions between these scenarios.

# 7. Counterfactual Resection Search

This is one of the most advanced components.

Given:

```text
Target epileptogenic zone
+
anatomical constraints
+
regions that should preferably be preserved
```

the system generates possible resection scenarios.

Conceptually:

```text
Original Proposed Resection
           │
           ▼
 Candidate Generator
           │
    ┌──────┼──────┐
    ▼      ▼      ▼
   R1     R2      R3
    │      │       │
    ▼      ▼       ▼
 Network Simulation
    │      │       │
 ML Outcome Prediction
    │      │       │
    └──────┼───────┘
           ▼
   Trade-Off Analysis
```

Objective function example:

```text
Minimize:

network disruption
+
hub destruction
+
language-network disruption

while:

maintaining sufficient target coverage
```

Important:

The system should label this:

**Research Counterfactual Analysis**

not:

**Recommended Surgery**

The system must never present itself as autonomous surgical advice.

# 8. Multi-Atlas Support

Brain regions depend on the selected parcellation atlas.

NeuroResect should treat an atlas as a pluggable abstraction.

```text
Atlas Interface

├── Desikan-Killiany
├── Destrieux
├── Schaefer-100
├── Schaefer-200
├── AAL
└── Future Atlases
```

Every atlas provides:

```text
atlas_id
region_names
region_labels
region_meshes
coordinates
hemisphere
parent_network
adjacency_mapping
```

A researcher should be able to switch:

```text
Schaefer-100
        ↓
Schaefer-200
```

and rerun the same experiment.

This enables atlas sensitivity analysis.

Example UI:

```text
Atlas Robustness

Schaefer-100     0.81 AUC
Schaefer-200     0.79 AUC
Desikan          0.77 AUC

Prediction consistency: 87%
```

# 13. Graph Engine

This is one of the most important modules.

Input:

```text
Connectivity Matrix

N × N
```

Example:

```text
       A    B    C    D

A      0   .84  .31  .02
B     .84   0   .62  .15
C     .31  .62   0   .76
D     .02  .15  .76   0
```

Converted into:

```text
Graph G = (V, E)
```

Graph engine calculates:

### Node-Level Metrics

* degree;
* weighted degree;
* betweenness;
* eigenvector centrality;
* participation coefficient;
* hub status.

### Graph-Level Metrics

* global efficiency;
* characteristic path length;
* modularity;
* network density;
* clustering;
* assortativity;
* small-world characteristics.

---

# 14. Virtual Resection Engine

Input:

```text
Patient graph
+
Resection mask
```

Output:

```text
Post-resection graph
```

Three strategies should be available.

### Binary Resection

Region removed completely.

```text
weight = 0
```

### Weighted Resection

If 35% of a region was resected:

```text
remaining_weight = original_weight × 0.65
```

### Edge-Informed Resection

Connections passing through the resection mask are weakened based on tract involvement.

This would be an advanced version.

---

# 15. Delta Feature Engine

Calculate:

```text
Δfeature = post-resection feature - pre-resection feature
```

Examples:

```text
Δ global efficiency

Δ modularity

Δ hub centrality

Δ interhemispheric connectivity

Δ temporal-network connectivity
```

These deltas become ML features.

Interpretability and proper validation matter more than using the newest architecture.

# 25. Visual Resection Effect

Do not make the brain simply disappear instantly.

Use animation.

### Step 1

Selected region glows.

### Step 2

Resection boundary appears.

### Step 3

Region becomes translucent.

### Step 4

Connections affected by resection progressively disappear.

### Step 5

Network reorganizes visually.

### Step 6

Metrics animate from:

```text
Before

Global Efficiency
0.64
```

to:

```text
After

Global Efficiency
0.52

▼18.7%
```

Duration:

roughly 800–1200 ms.

Subtle.

Not flashy.

# 43. Performance

3D data must not freeze the browser.

Use:

```text
precomputed brain meshes

compressed GLTF

Web Workers

lazy loading

level-of-detail meshes

GPU instancing

edge thresholding
```

Do not render:

```text
50,000 connectivity edges
```

simultaneously.

Render strongest edges or aggregate connections.

**Actual Resection**

**Simulate Resection**

```text
Global efficiency
```

```text
Favorable outcome

71%

Confidence

Moderate
```

```text
Resection Margin

+3mm
```

The 3D brain changes.

Network metrics recalculate.

Prediction changes:

```text
71% → 62%
```

# 52. Final Product Identity

## NeuroResect

### Patient-Specific Virtual Resection and Brain Network Analysis for Epilepsy Research

The project should not position itself as:

**an epilepsy prediction app.**

It should position itself as:

> A research platform for investigating how patient-specific surgical interventions alter brain-network topology and how those alterations relate to postoperative outcomes.
